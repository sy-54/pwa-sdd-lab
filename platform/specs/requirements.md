# PWAランチャー 要求仕様

> Claudeで作った小さなWebアプリを、iPhoneのホーム画面からすぐ使えるようにする基盤。
> 1つのPWAから複数のミニアプリを一覧・起動し、共通SDKで保存・UI・通知・カメラを提供する。
> 静的ホスティングだけで動き、サーバー側の処理は持たない。

目的：Claudeで作った小さなWebアプリを、iPhoneのホーム画面からすぐ使えるようにする。
利用者：本人（個人利用）。

## Must
- ホーム画面に追加できる1つのPWAから、複数のミニアプリを一覧して起動できる
- ミニアプリは「1フォルダ＝manifest＋index.html」で追加でき、git pushで公開される
- アプリごとにデータを端末内に保存できる。オフラインでも起動できる
- 共通SDK：保存、UI部品、通知、カメラ
- 公開前に自動チェック（manifestの検証、E2E）を通す

## Should
- データのエクスポート／インポート
- ダークモード対応

## Won't
- Bluetooth、HealthKit、複数ユーザー対応、サーバー側の処理

## 制約
- iOS Safari（ホーム画面に追加したPWA）で動くこと
- 静的ホスティング（GitHub Pages / Cloudflare Pages）で動くこと

## UI契約
- 各ミニアプリのルート要素は data-testid="app-root"

## 改訂履歴
- 変わった点：通知は「アプリ内トースト＋起動中の OS 通知」に限定した。時刻指定・閉じている間の通知はサーバーが要るためやらない（D2）
- 変わった点：ミニアプリはページ遷移で開き、戻る手段は SDK のヘッダーが提供する（D3）
- 変わった点：Should の2件を最小限で入れた。ダークモードは OS 追従のみ、エクスポート／インポートは全アプリ一括の JSON（D4）
- 変わった点：公開先は GitHub Pages（公開リポジトリ）。サブパス公開のため URL はすべて相対パス（D1, D5）
- 分かった点：WebKit は環境により IndexedDB に Blob を直接保存できない。SDK が ArrayBuffer に変換して保存する
- 分かった点：ホーム画面から起動した iOS ではファイルを直接ダウンロードできない。エクスポートは共有シートで渡す
- 分かった点：テスト環境の WebKit は OS 通知に未対応。E2E はトースト代替だけを確かめ、OS 通知は実機で確かめた
- 実機確認（11/14、iPhone）：ホーム画面からの起動、保存、OS 通知、カメラ、オフライン起動、書き出しの6項目すべて OK
- 次に活かす点：通知・カメラは「どこまでやるか」を Must に書く。デプロイ先は制約に確定で書く
- 次に活かす点：UI契約にランチャー側の data-testid も書く（今回は spec で決めた）
