# ToDo 要求仕様

> やることを書き留めて、済んだら消し込むリスト。
> 追加・完了・削除ができ、残りの件数が分かる。
> 思いついた瞬間にすぐ書けることが大事。

目的：その日のやることを忘れないようにする。
利用者：本人（個人利用）。

## Must
- やることを追加できる
- 完了／未完了を切り替えられる
- 削除できる
- 残っている件数が分かる
- アプリを閉じて開き直しても内容が残る

## Should
- 完了したものは見た目で区別できる

## Won't
- 期限、並べ替え、カテゴリ、複数リスト

## 制約
- platform の SDK を使う（`sdk/README.md`）。静的ファイルのみ

## UI契約
- エントリ：`apps/todo/index.html`（`apps/todo/manifest.json` も置く）
- ルート要素：`data-testid="app-root"`
- 入力欄：`data-testid="new-todo"`、追加ボタン：`data-testid="add"`。入力欄で Enter を押しても追加される
- 各項目：`data-testid="todo-item"`。その中に `"todo-text"`（内容）、`"todo-toggle"`（`input type="checkbox"`）、`"todo-delete"`（ボタン）
- 残り件数：`data-testid="todo-count"`（テキストは数字のみ）

## 改訂履歴

### 分かった点
- 入力テキストの先頭末尾の空白をトリムしてから判定する必要があった（空白のみの入力は追加されない）
- 非同期の保存処理完了を待たずに UI を即座に更新する（メモリ上の状態が先行する）
- データ検証時に配列型確認の後、各要素が `{ text, completed }` 形式かチェック

### 次に活かす点
- 「空欄」と「空白のみ」の区別を明確に記述（前処理の仕様を明記する）
- 複数操作が連続する場合の保存順序について明記
- エラーメッセージの具体的な文言（「保存に失敗しました」「データをリセットしました」）を初期要求に含める
