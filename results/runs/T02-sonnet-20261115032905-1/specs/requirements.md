# ToDo 要求仕様

> やることを書き留めて、済んだら消し込むリスト。
> 追加・完了・削除ができ、残りの件数が分かる。
> 思いついた瞬間にすぐ書けることが大事。

目的：その日のやることを忘れないようにする。
利用者：本人（個人利用）。

## Must
- やることを追加できる
- 完了／未完了を切り替えられる
- 削除できる
- 残っている件数が分かる
- アプリを閉じて開き直しても内容が残る

## Should
- 完了したものは見た目で区別できる

## Won't
- 期限、並べ替え、カテゴリ、複数リスト

## 制約
- platform の SDK を使う（`sdk/README.md`）。静的ファイルのみ

## UI契約
- エントリ：`apps/todo/index.html`（`apps/todo/manifest.json` も置く）
- ルート要素：`data-testid="app-root"`
- 入力欄：`data-testid="new-todo"`、追加ボタン：`data-testid="add"`。入力欄で Enter を押しても追加される
- 各項目：`data-testid="todo-item"`。その中に `"todo-text"`（内容）、`"todo-toggle"`（`input type="checkbox"`）、`"todo-delete"`（ボタン）
- 残り件数：`data-testid="todo-count"`（テキストは数字のみ）

## 改訂履歴
- 変わった点：空/空白のみの入力・重複・文字数上限なし（D1）、追加ボタンは常に有効（D2）、新規項目は末尾追加（D3）、削除は確認なしで即時（D4）、完了切替で位置を変えない（D5）を qa.md のQ1〜Q5で確定した。いずれも Must/Should の記述を具体化したもので、要求そのものの変更はない。
- 分かった点：壊れた保存データ（配列でない、要素が `{ id, text, done }` の形でない）は空の一覧として扱う、という復元時のエラー処理は要求に明記がなく、実装時に spec.md で定めた。
- 次に活かす点：再描画処理（画面更新用の関数）は呼び出し元より先に実装し、単体テストだけでなくE2Eで画面が実際に更新されるかまで確認する。本アプリでも `main.js` で未定義の関数を呼んでいた不具合をE2E作成時に発見して修正した。
