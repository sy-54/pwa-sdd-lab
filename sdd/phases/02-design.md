# フェーズ2：design（設計）

入力：`requirements.md`、承認済みの `spec.md`　出力：`design.md`（100行以内、雛形 `templates/design.md`）

## 手順
1. `spec.md` を読む。SDK を使う環境では SDK の API 一覧も読む。
2. `design.md` を書く。
3. lint を `--phase design` で実行し、OK にする。人間に承認を求めて止まる。

## 書き方
- **モジュール構成**：ファイルごとに責務を1行で。**ロジックは DOM に触れない純粋関数のモジュール**に分け、画面（DOM・イベント・保存の呼び出し）と分離する。ロジックは単体テスト、画面は E2E で確認するため。
- **データモデル**：保存するキーと値の形を具体例つきで。壊れた値を読んだときの扱いも書く。
- **使用するSDK API**：使う関数名を列挙する。使わないなら「なし」と理由。SDK にある機能を自作しない。
- **ACとテストの対応**：全 AC を表にする。列は「AC／単体テスト／E2E」。単体で確かめられない AC は単体を「―」とする。
- spec の内容を繰り返さない。spec にない振る舞いが必要になったら、design に書かず spec を直す。
- フレームワークやビルド手順を増やさない。必要なら理由を1行書く。
- ブラウザや OS の機能に頼る箇所（保存形式、通知、カメラ、オフラインなど）は、**テスト環境で確かめられるか**を対応表に書く。確かめられないものは代わりの確認方法（代替入力、実機確認）を書く。
