# フェーズ3：tasks（タスク分解）

入力：`spec.md`、`design.md`　出力：`tasks.md`（50行以内、雛形 `templates/tasks.md`）

## 手順
1. `design.md` のモジュールと対応表から、タスクを実装順に並べる。
2. lint を `--phase tasks` で実行し、OK にする。

## 書き方
- 形式は1行1タスク：`- [ ] T01: 内容 (AC-01, AC-02)`。AC に紐づかない準備作業は末尾を `(setup)` にする。
- **1タスクは1時間以内、1コミット**で終わる大きさ。「テストを書く」と「実装する」を別タスクにしない（1タスクの中で Red→Green を回す）。
- 並べ方：①土台（UI契約にあるファイルと `data-testid` をすべて置く静的マークアップ）→ ②ロジック（単体テストから）→ ③画面の結線 → ④保存・エラー処理 → ⑤最後に「全 AC の E2E を書いて通す」。
- すべての AC が、どれかのタスクに現れること。
- 内容には、触るファイルと確かめ方が分かる程度の具体性を持たせる。
- 動くかどうか不確かな技術要素（初めて使う API、環境依存の機能）は、**早い順番のタスク**で小さく確かめる。後ろに回すと設計のやり直しが大きくなる。
- 人間にしかできない作業（実機確認、アカウント設定）もタスクとして書き、末尾を `(setup)` にする。
