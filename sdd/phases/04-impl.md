# フェーズ4：impl（TDDで実装）

入力：`spec.md`、`design.md`、`tasks.md`　出力：コード、単体テスト、チェック済みの `tasks.md`

## 手順（未完了タスクを上から1つずつ）
1. **Red**：そのタスクの AC を満たす単体テストを先に書き、失敗することを実行して確かめる。
2. **Green**：テストが通る最小の実装を書く。全単体テストを実行して通す。
3. **Refactor**：重複や分かりにくい名前を直す。テストは通ったまま。
4. `tasks.md` の該当行を `- [x]` にして、**1タスク1コミット**（`T01: 内容`）。
5. 次のタスクへ。E2E のタスクはフェーズ5の手順書に従う。

## ルール
- design のモジュール構成とデータモデルに従う。変える必要があれば先に `design.md` を直す。
- UI契約と spec の `data-testid` は一字一句そのまま使う。
- DOM を触るだけで単体テストにできないタスク（マークアップ、結線）は、テストなしで実装してよい。その AC は E2E で確かめる。
- テストを通すためにテストを弱めない。spec と食い違うテストは、spec を正としてテストを直す。
- 指定された範囲の外（別アプリ、SDK、設定ファイル）は変えない。
- 終わったら全単体テストを実行し、結果を報告する。
