# フェーズ5：integration / E2E

入力：`spec.md` の全 AC、実装済みのアプリ　出力：E2Eテスト（Playwright WebKit）

## 手順
1. AC ごとに1本以上のテストを書く。**テスト名を AC の ID で始める**：`test('AC-01 増やす', …)`。
2. Given を操作で作り、When を実行し、Then を `data-testid` で検証する。
3. E2E を実行し、全件通す。落ちたら**実装を直す**（spec が正）。spec の誤りなら spec を直す。
   - 複数のテストが一度に落ちるときは、画面のスクリプトがエラーで止まっていることが多い。まず `page.on('pageerror', (e) => console.log(e.message))` を仕込んで1件だけ実行し、エラーを確かめる。
   - テストを通すために、期待値を spec と違う値に書き換えない。
4. lint を `--phase e2e` で実行し、OK にする。`tasks.md` の E2E タスクをチェックしてコミットする。

## ルール
- 要素は `page.getByTestId('…')` で取る。CSS クラスや文言に依存しない。
- テストは互いに独立させる。毎回まっさらな状態から始める（Playwright は各テストで保存領域が空になる）。
- 「再読み込み後も残る」は `page.reload()` で確かめる。
- 入力した値が使われることは、**初期値と違う値**で確かめる（初期値のままでは、入力を無視して初期値を使う実装でも通ってしまう）。
- 「何も起きない」ことは、**起きるはずの時間や操作を進めた後**で確かめる（タイマーなら時計を数秒進める、保存なら再読み込みする）。押した直後に見るだけでは、遅れて起きる誤動作を見逃す。
- 固定時間の待ち（`waitForTimeout`）を使わない。`expect(...).toHaveText()` などの自動待機を使う。
- 不正な入力の AC は、spec に挙げた値を**全部**試す（空、空白だけ、0、負、小数、文字）。1つだけ試して済ませない。
- 並び順や繰り返しの AC は、**3件以上**で確かめる（2件では、別の並べ方でも偶然通ることがある）。
- エラー時の挙動の AC は、壊れた保存データを `page.addInitScript` や `page.evaluate` で仕込んで確かめる。
- 画面のない AC（コマンド、ビルド、検証スクリプト）は、E2E テストの中からコマンドを実行して、終了コードと出力を確かめる。
- 時間や日付に依存する AC は、実時間を待たずに `page.clock.install()` で時計を偽装して進める。動いている最中の表示（カウントダウンなど）は `page.clock.runFor(ms)` で確かめる（途中のタイマーが順に動く）。`fastForward(ms)` は一気に飛ぶので、閉じていた間の時間経過を再現するときだけ使う。
